# 合同模板维护指南（自己改占位符与标记色）

> 适用：契衡合同管理系统（模板中心）。核心一句话：**母版（Word）是字段的唯一来源**——字段名最终必须体现在母版的占位符上。

---

## 一、动手前：拿到"当前母版"

模板中心 → 打开模板 → 在目标版本那一行：

| 按钮 | 是什么 | 什么时候用 |
| --- | --- | --- |
| **Word** | 下载**渲染母版**（系统实际用来生成合同的文件） | **推荐从这里改**。如果之前是靠颜色/下划线自动识别的，这里已经是 `{{auto_1}}` 形式，直接改最省事 |
| **原始上传件** | 自动识别**之前**你上传的原件 | 想对照改动痕迹、或想重新识别时用 |

⚠️ **已发布版本不能改**。要改先点「创建版本」（会复制当前版本）→ 在**新草稿版本**上改 → 走完校验/试填/确认/发布 → 已有合同点「升级到 Vx」。

## 二、三种"标记待填位置"的写法（任选，可混用）

### 做法 1：直接写 `{{字段名}}`（最可控，推荐长期用）
- 语法：`{{key}}`。key 必须 **小写字母开头**，只能含小写字母、数字、下划线，长度 ≤64。建议用语义化英文名：`party_b_name`、`amount`、`sign_date`。
- **同一个字段多处出现就写同一个 key**（例：乙方名称在首部和盖章处都写 `{{party_b_name}}`），填一次处处一致。
- **必须遵守的 5 条**（否则校验会被拒）：
  1. 不能跨段落（中间不能有回车）；
  2. 不要写在文本框、形状、域代码（如页码域）、脚注、批注、修订痕迹里；
  3. 不要写在**合并过的单元格**（横向/纵向合并）里；
  4. 一个占位符内部**不要改格式**（不要一半加粗一半不加粗）。Word 把它拆成多个 run 是正常的，系统能处理，但样式必须一致；
  5. 只支持纯小写 key，不要写 `{% ... %}`、`{{A.B}}`、`{{ 带空格 }}`。
- 小技巧：想让**填进去的值带下划线**（合同常见填空横线效果）：先把光标 `Ctrl+U` 打开再输入 `{{key}}`，输完再 `Ctrl+U` 关掉。值会继承下划线，且长度随内容变化。

### 做法 2：用颜色标记，让系统自动转成占位符
1. 版本行的 **「标记色」**（默认 `#ff0000`，会记住你上次选的色值）；
2. 在 Word 里选中待填文字 → 字体颜色 → **其他颜色 → 自定义**，输入同一个色值（**不要用"主题颜色"**，那会写成 themeColor 可能匹配不上；用"标准色"里的红色就是 `FF0000`）；
3. 上传 → 系统把这些彩色文字换成 `{{auto_N}}`，并自动给中文名（取标记前面的文字，如"乙方名称："→ `乙方名称`）。
- 细节：**相邻同色文字自动合并成一个字段**（Word 常把一个词拆成多个 run，不会变成多个字段）；标记色会被**清除**，生成出来的值是正常黑色；只给空白上色（没有文字）也能识别。
- 适合：母版已经是"成品合同"（值都写死了），你用颜色刷一遍就变成可填报模板。

### 做法 3：连续下划线 ≥3 个
- 直接把待填位置写成 `___`（半角）或 `＿＿＿`（全角）三个以上即可，不用上色。
- 2 个及以下**不会**被识别（防止把"＿＿月"这类误判成字段）。

> 三种可混用：**颜色先编号**（auto_1…auto_k），**下划线接着编号**（auto_k+1…）。

## 三、上传之后：字段配置怎么处理

### 系统自动做的
- **原来没有字段配置** → 自动建出全部字段：中文名优先用内置词典（合同编号/甲方名称/合同金额…），其次用标记上下文；类型按名字猜（`*_date`→日期、含 amount/price/rate→金额、`*_qty/_days/_ratio`→整数、`*_upper`→金额大写自动计算）；**默认不勾必填**。
- **上传母版时字段配置自动与母版对齐**（母版是字段的唯一来源）：
  - 母版里**新增**的占位符 → 自动补成字段（原有字段的顺序和设置不动），提示"新增 N 个"；
  - 配置里有、但**母版里已经不存在**的字段 → 自动删掉，提示"删除 N 个（母版里已不存在）"。
  这样"复制版本后换了另一份母版"不会留下对不上的旧字段（被删掉的字段名记录在该版本的 `VERSION_FIELDS_SYNCED` / `TEMPLATE_UPLOADED` 审计里，需要时可查回来）。**只作用于草稿版本**：已发布版本的母版和字段都不可改，历史合同也不受影响。
  - 删字段容易"连带弄坏引用"，所以同步时会**顺手修复引用**：金额大写的来源指向了被删掉的金额字段 → 只有一个同族金额字段（如 `amount_upper` → 唯一的 `amount_*`）就自动接上，有多个候选就不猜、改成手填金额；日期先后引用了不存在的日期 → 取消该比较；字段挂在已不存在的分组 → 归入第一个分组。修复内容会在提示和审计里写明。
- 如果只想在**现有配置**上对齐（不重新上传母版）：打开「字段配置」→ 点【**按母版同步字段**】，效果同上（会先弹确认框）。

### 需要你自己做的
| 按钮 | 作用 |
| --- | --- |
| **字段配置** | 弹窗顶部有**填充位置核对表**（字段 \| 母版中出现几处 \| 首处附近文字），下面是 JSON 编辑区；出现 0 处的字段会标红"母版中没找到"，母版里有但配置里没有的占位符会在下方红字列出 |
| **按母版同步字段**（在「字段配置」里） | 一键按母版增删字段，修掉"字段绑定不匹配：母版中不存在 …"这类报错 |
| **字段名中文化** | 把"显示名还是英文 key"的字段按内置词典**批量改中文**（只改显示名，不动类型/必填/绑定） |
| **重命名** | 给这个版本起个名字（纯元数据，不影响试填确认） |
| **校验** | 检查"母版占位符 ↔ 字段配置"是否完全对应 |
| **试填 / 查看试填 PDF / 确认试填 / 发布** | 发布前的四步。**试填 PDF 是核对"值填到哪"最直观的方式** |
| **彻底删除版本** | 物理删除草稿版本，**版本号会被释放**，下个新版本会重新用它 |

### 值会填到哪里（重要）
- **标哪填哪**：只有被标记（`{{key}}` / 颜色 / ≥3 下划线）的位置会被替换成值；系统**不移动正文、不新增内容**，也不会填到没标记的地方。
- **同一个 key 多处出现 → 填同一个值**：例：`{{party_b_name}}` 在首部与盖章处各一处，填一次两处自动一致。
- **格式跟着标记走**：标记处是下划线/加粗/某字号，值就继承同样格式（所以"填空横线"效果＝给占位符加下划线）。
- **核对位置的两个办法**：①「字段配置」里的位置核对表；②直接试填并打开试填 PDF 看每个值落在哪。

### 字段配置常用片段（贴进 `fields` 数组）
```json
{"key":"amount","label":"合同总金额（元）","type":"money","group":"base","order":1,"required":true,"binding":"amount","scale":2,"min":"0.00","max":"999999999.99"}
{"key":"amount_upper","label":"金额大写","type":"computed","group":"base","order":2,"binding":"amount_upper","calculator":"rmb_upper","source":"amount"}
{"key":"sign_date","label":"签署日期","type":"date","group":"base","order":3,"binding":"sign_date","format":"chinese"}
{"key":"qty","label":"数量","type":"integer","group":"base","order":4,"binding":"qty","min":1,"max":100000}
{"key":"pay_type","label":"付款方式","type":"select","group":"base","order":5,"binding":"pay_type","options":["电汇","承兑汇票"]}
{"key":"tax","label":"是否含税","type":"boolean","group":"base","order":6,"binding":"tax","true_label":"含税","false_label":"不含税"}
{"key":"party_b_name","label":"乙方名称","type":"text","group":"base","order":7,"required":true,"binding":"party_b_name","max_length":100}
{"key":"scope","label":"项目范围","type":"textarea","group":"base","order":8,"binding":"scope","max_length":3000}
{"key":"end_date","label":"结束日期","type":"date","group":"base","order":9,"binding":"end_date","after":"start_date"}
```

关键规则：
- `key` 必须**与母版里的占位符同名**；`binding` 也必须是同一个 key（两者不一致会被拒）。
- `required: true` → 生成/定稿前必须填写；不写或 false → 可留空。
- `group` 必须是 `groups` 里已存在的分组 key（默认有一个 `base`＝合同信息）。
- `computed` 只能配 `calculator: "rmb_upper"` 且 `source` 指向一个 `money` 字段。
- `date` 的 `after` 用来做"结束日期不得早于开始日期"的跨字段校验，值填另一个 date 字段的 key。

## 四、改完必须走的验证（4 步，缺一不可）

1. **校验** → 通过说明母版占位符与字段配置完全对应；
2. **试填** → 系统用样例值生成一份文件；
3. **查看试填 PDF** → 必须点开看（不点开，下一步会被拒："请先打开本次生成的完整 PDF"）；
4. **确认试填** → **发布**。

> 试填确认绑定的是"当时那份母版 + 字段配置"的指纹：**只要改了母版或字段配置，就要重新试填+确认**（系统会提示"发布前必须完成当前母版及字段配置的试填和全文确认"）。

## 五、常见报错对照表

| 报错 | 原因 | 怎么办 |
| --- | --- | --- |
| 母版中未找到 {{占位符}}，也没有识别到标记… | 上传的 DOCX 里既没有 `{{}}`，也没有 ≥3 下划线、也没有标记色文字 | 按上面三种做法之一标记后重新上传 |
| 字段绑定不匹配；**未配置**：xxx | 母版里有 `{{xxx}}`，字段配置里没有 | 上传时会自动补；或打开「字段配置」点【按母版同步字段】；也可手工加一条 |
| 字段绑定不匹配；**母版中不存在**：xxx（常见于"复制版本/换了另一份母版"） | 配置里有 xxx，但当前母版里没有该占位符 | 打开「字段配置」点【**按母版同步字段**】（自动删掉这些字段）；或重新上传一次母版（上传也会自动对齐）；确实需要这个字段就在母版里补 `{{xxx}}` |
| 占位符跨越不同样式，请在 Word 中重新输入… | 占位符中间换了字体/加粗/字号 | 全选占位符→清除格式→重新输入；或先设好格式再输入 |
| 占位符位于不支持的文本框、域或内容控件内 | 写在了文本框/内容控件/域里 | 移到正文段落或普通表格单元格 |
| 合并单元格内的占位符需移入普通单元格 | 写在横向/纵向合并的单元格里 | 取消合并，或换到普通单元格 |
| 存在未知表达式或跨段占位符 | 写了 `{% %}`、`{{A.B}}`、大写 key，或占位符跨了段落 | 改成合法的 `{{小写key}}`，放在同一段内 |
| 已发布版本不可修改，请复制新版本 | 想直接改已发布版本 | 「创建版本」→ 在新草稿上改 → 重新发布 |
| 模板已更新，请先升级合同 | 合同还固定着旧模板版本 | 合同详情点「升级到 Vx」 |
| 人民币大写必须依赖一个金额字段 | 计算字段（`*_upper`）的 `source` 指向的金额字段已经不存在了（按母版删字段后最常见） | 点【**按母版同步字段**】：只有一个同族金额字段会自动接上，多个候选则改为手填金额字段；也可以自己在 JSON 里把 `source` 改成正确的金额 key |
| 字段引用了不存在的分组 | `fields[].group` 里的 key 不在 `groups` 里（例如只粘了 `fields` 数组、没粘 `groups`） | 点【按母版同步字段】会自动归入第一个分组；或补齐 `groups` |
| 当前母版里没有 {{占位符}}，所以没有可配置字段 | 字段配置是空的 | 先按三种做法标记母版再上传 |

## 六、两条经验（能省很多时间）

1. **先定 key，再排版**：占位符先用纯文本写好（如 `{{party_b_name}}`），确认校验通过后再调整字体、下划线、表格布局——避免边排版边改占位符导致"跨样式"报错。
2. **改动幅度大就新建版本**：小改（改中文名、必填、长度）直接改字段配置；一改母版内容或加删占位符，最好新建版本，这样历史合同仍能追溯到旧版式。
