# 契衡合同管理系统 · 部署与运维手册

> 面向负责安装、升级、备份和排查的运维/管理员。业务操作见 [使用手册.md](使用手册.md)，模板制作见 [模板维护指南.md](模板维护指南.md)。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| **JDK** | 21（Temurin/OpenJDK 均可） | 启动脚本用的是 PATH 里的 `java`；`java -version` 应显示 21.x |
| **LibreOffice** | 最新稳定版 | 生成 PDF 必需。默认装在 `C:\Program Files\LibreOffice`；装在别处就设 `LIBREOFFICE_PATH` |
| **PostgreSQL** | 16（Docker 或本机安装） | 正式使用推荐；也可用内嵌 H2 文件库（零依赖，适合单机小规模） |
| **Docker Desktop** | 最新版（可选） | 用 `一键启动契衡系统.bat` 时用它跑 PostgreSQL 容器 `qiheng-postgres` |
| 磁盘 | 视合同量 | `STORAGE_ROOT` 存放母版与生成文件（每个合同每版约几百 KB） |

内存/CPU：单机 2 核 4 GB 足够小团队使用；生成是串行队列（`WORKER_CONCURRENCY=1`），并发填报人数多时可调到 2～3。

## 二、安装与启动

### 方式 A：一键脚本（Windows，含 Docker）

1. 安装 JDK 21、Docker Desktop、LibreOffice。
2. 启动 Docker Desktop（等托盘图标变绿）。
3. 双击 `一键启动契衡系统.bat`：检查 Docker → 建/启 `qiheng-postgres` → **等数据库真正可连接** → 设环境变量 → 后台启动 jar → 轮询 `/api/v1/health` → 打开浏览器。

停止：双击 `停止契衡系统.bat`，或关闭那个最小化的 `Qiheng` 命令行窗口。

### 方式 B：手工启动

```bat
set DATABASE_URL=jdbc:postgresql://127.0.0.1:5432/qiheng
set DATABASE_USERNAME=qiheng
set DATABASE_PASSWORD=<你的密码>
set STORAGE_ROOT=D:\qiheng\data\files
set PORT=8080
set BIND_ADDRESS=0.0.0.0
set SECURE_COOKIE=false
set LIBREOFFICE_PATH=C:\Program Files\LibreOffice\program\soffice.exe
java -jar target\ContractHub-1.0.0.jar
```

### 首次创建管理员（必须，只能用命令行）

```bat
java -jar target\ContractHub-1.0.0.jar --init-admin --username=admin --display-name=系统管理员 --password=<随机强密码>
```

- 密码至少 6 位、不能是常见弱密码；首次登录会强制改密。
- 系统**没有**网页注册或初始化后门；`--init-admin` 只在本地命令行可用。
- 管理员密码丢失时用 `--recover-admin`（重置该账号，不动业务数据）。

## 三、网络与访问

| 需求 | 配置 |
| --- | --- |
| 只本机使用（默认） | 什么都不用改（`BIND_ADDRESS=127.0.0.1`） |
| 局域网其他电脑访问 | 启动脚本里加 `set BIND_ADDRESS=0.0.0.0`，防火墙放行 TCP 8080，访问 `http://<服务器IP>:8080/` |
| 换端口 | `set PORT=8081`（并把启动脚本里健康检查用的 8080 一起改） |
| HTTPS | 前置 Nginx/IIS 反向代理，设 `SECURE_COOKIE=true`；若代理可信再设 `TRUST_FORWARDED_HEADER=true`（否则登录限速可被伪造来源绕过） |
| 固定域名 | 内网 DNS 或各电脑 hosts 指向服务器 IP |

## 四、配置项

## 五、备份与恢复

**必须同时备份两样**：数据库 + `STORAGE_ROOT` 文件目录。少一样都会丢数据（合同正文在数据库里，母版和生成文件在磁盘上）。

```bat
rem 1) 数据库
docker exec -e PGCLIENTENCODING=UTF8 qiheng-postgres pg_dump -U qiheng -d qiheng --no-owner --no-privileges -f /tmp/backup.sql
docker cp qiheng-postgres:/tmp/backup.sql D:\backup\qiheng-%DATE%.sql

rem 2) 文件
xcopy /Y /E /I "D:\qiheng\data\files\*" "D:\backup\files\"
```

恢复（把快照导回空库）：

```bat
docker exec qiheng-postgres psql -U qiheng -d qiheng -c "DROP SCHEMA IF EXISTS public CASCADE; CREATE SCHEMA public;"
docker cp D:\backup\qiheng-xxxx.sql qiheng-postgres:/tmp/restore.sql
docker exec -e PGCLIENTENCODING=UTF8 qiheng-postgres psql -U qiheng -d qiheng -v ON_ERROR_STOP=1 -f /tmp/restore.sql
```

> 恢复前先停应用，避免写入冲突。确认行数：`select count(*) from contracts; select count(*) from files;`

## 六、迁移到另一台电脑

要点：**只拷源码是不够的**——数据库在 Docker 卷里、上传与生成的文件在 `STORAGE_ROOT`。标准做法是打一个"迁移包"：

```
迁移包/
├─ target\ContractHub-1.0.0.jar      程序
├─ data\files\                       上传与生成的文件
├─ db\qiheng-db.sql                  数据库快照
├─ 一键启动契衡系统.bat / start.bat / 停止契衡系统.bat
└─ 首次初始化数据库.bat              新机器上跑一次：建容器 + 导入快照
```

新机器上的步骤：

1. 装 JDK 21 + Docker Desktop + LibreOffice。
2. 把迁移包放到**不含中文和空格**的路径（例如 `D:\ContractHub`）。
3. 双击 `首次初始化数据库.bat`（建容器 → 等库就绪 → 清空 public schema → 导入快照）。
4. 双击 `一键启动契衡系统.bat`，用**原来的账号密码**登录（用户表与密码哈希都在快照里）。

**内网离线**：在能上网的机器上 `docker save postgres:16 -o postgres16.tar`，拷过去 `docker load -i postgres16.tar`，这样第一次建容器不需要联网拉镜像；三个安装包也要提前拷。

**搬运前请重新导出快照**（数据是动态的），并注意：快照含全部业务数据与账号，属于敏感文件，别放公共位置。

## 七、升级

1. 备份（见第五节）。
2. 停应用。
3. 用新的 `ContractHub-1.0.0.jar` 覆盖 `target\` 下的 jar。
4. 启动：Flyway 会自动执行新增的迁移脚本（`src/main/resources/db/migration/V*.sql`），日志里会打印 `Successfully validated N migrations`。
5. 登录后到「系统状态」和「审计日志」确认正常。

> 升级只需换 jar，不用重装数据库；**不要**手工改数据库结构，迁移脚本才是一致性的来源。

## 八、日常运维

| 事项 | 做法 |
| --- | --- |
| 日志 | `data/application.log`（启动脚本重定向到这里）；查错先看最后 50 行 |
| 健康检查 | `curl http://127.0.0.1:8080/api/v1/health` 返回 `{"status":"UP",...}` |
| 系统状态 | 管理员登录 → 系统状态（数据库、文件存储、生成服务） |
| 孤儿文件回收 | 默认开启，每小时清理无数据库引用的临时文件（保留 `ORPHAN_RETENTION_HOURS=24` 小时） |
| 生成失败排查 | 看日志里的任务错误码；多为 LibreOffice 路径不对、字体缺失、文件过大 |
| 改数据库密码 | 改容器 `POSTGRES_PASSWORD` 与启动脚本里的 `DATABASE_PASSWORD`，两处保持一致 |
| 磁盘增长 | 主要来自 `STORAGE_ROOT`；作废/删除合同后对应文件会被回收 |

## 九、故障排查

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 启动脚本提示 `Docker Desktop is not running` | 先启动 Docker Desktop 并等它就绪 |
| `PostgreSQL startup timeout` | 容器没起来；`docker logs qiheng-postgres`；或 5432 被占用 |
| `Java startup failed. See data\application.log` | 端口被占、数据库连不上、JDK 版本不对（必须 21） |
| 数据库连不上（日志里 `Connection refused`） | 容器未启动 / 密码不一致 / `DATABASE_URL` 写错 |
| 生成 PDF 失败 | 未安装 LibreOffice 或路径不对；`LIBREOFFICE_PATH` 指向 `soffice.exe` |
| PDF 中文变方块 | 服务器缺中文字体（中文版 Windows 自带；Linux 装 Noto CJK） |
| 上传报"文件过大" | 超过 `MAX_UPLOAD_MB`（默认 30MB） |
| 页面能开但接口 403 | CSRF 令牌缺失（正常由前端自动带）；用接口调试时先 `GET /api/v1/auth/csrf` |
| 登录一直 429 | 失败限速；等 15 分钟或调高 `LOGIN_ACCOUNT_LIMIT` / `LOGIN_SOURCE_LIMIT` |

## 十、安全建议（正式环境）

1. **改掉默认数据库口令**（脚本里的 `POSTGRES_PASSWORD`），数据库端口只绑 `127.0.0.1`。
2. 只在可信内网开放 `BIND_ADDRESS=0.0.0.0`；有条件就上 HTTPS 并设 `SECURE_COOKIE=true`。
3. 服务器登录权限收紧，`data/` 目录（含合同文件）不要共享给无关人员。
4. 定期备份并**做一次恢复演练**（备份没验证过等于没有备份）。
5. 管理员账号一人一个，不要共用；人员离职立即停用账号或转移其合同所有者。
6. 需要查毒就配置 `SCAN_COMMAND`（上传后会调用），否则系统只做 DOCX 结构安全检查。
